# 03 接口设计（REST API）

> 驿迹 ExpressTrace ｜ 前后端契约文档，前后端分离开发的唯一事实来源
> 约定：JSON in / JSON out；时间一律 ISO 8601（含时区）；错误统一格式

## 1. 通用约定

**Base URL**：`http://localhost:3000/api/v1`

**统一响应封装**：

```json
// 成功
{ "code": 0, "message": "ok", "data": { ... } }

// 失败
{ "code": 40401, "message": "订单不存在", "data": null }
```

**错误码表**：

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200/201 | 成功 |
| 40001 | 400 | 参数校验失败 |
| 40002 | 400 | 轨迹时间早于最后一条（违反 BR-02） |
| 40401 | 404 | 订单不存在 |
| 40901 | 409 | 状态流转非法（如已签收仍追加，违反 BR-01） |
| 50000 | 500 | 服务器内部错误 |

**分页参数**（列表类接口）：`page`（默认 1）、`pageSize`（默认 10，最大 100）。

**分页响应结构**：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "items": [ ... ],
    "total": 123,
    "page": 1,
    "pageSize": 10
  }
}
```

## 2. 接口清单

| # | 方法 | 路径 | 功能 | 对应需求 |
|---|---|---|---|---|
| 1 | POST | `/orders` | 创建订单 | FR-01 |
| 2 | GET | `/orders` | 组合筛选订单列表 | FR-04 |
| 3 | GET | `/orders/{orderNo}` | 查订单详情（含全部轨迹） | FR-03 |
| 4 | POST | `/orders/{orderNo}/tracking` | 追加物流轨迹 | FR-02 / FR-07 |

## 3. 接口详情

### 3.1 创建订单 `POST /orders`

**请求体**：

```json
{
  "sender":   { "name": "张三", "phone": "13800000001", "address": "广东省深圳市南山区科技园路1号" },
  "receiver": { "name": "李四", "phone": "13900000002", "address": "北京市海淀区中关村大街2号" },
  "package":  { "weight_kg": 2.5, "quantity": 1, "category": "日用品", "remark": "易碎" }
}
```

**校验**：name/phone/address 必填；`weight_kg > 0`；`quantity` 为正整数。

**成功响应 `201`**：`data` 为完整订单文档，`order_no` 由后端按 BR-03 生成，`current_status = "CREATED"`，`tracking = []`。

### 3.2 组合筛选订单 `GET /orders`

**查询参数**（均可选，AND 组合）：

| 参数 | 示例 | 说明 |
|---|---|---|
| `status` | `IN_TRANSIT` | 按当前物流状态（枚举见 02 文档 §3） |
| `node` | `武汉中转场` | 按当前网点（精确匹配 `current_node`） |
| `start` / `end` | `2026-11-01` / `2026-11-17` | 下单时间范围（闭区间） |
| `order_no` | `ET20261117` | 单号前缀模糊 |
| `page` / `pageSize` | `1` / `10` | 分页 |

**排序**：`created_at` 倒序（走 `idx_created` 或 `idx_status_created`）。

**响应 `200`**：分页结构，`items` 为订单摘要（含 `current_status`、`current_node`、`tracking` 仅留最新 1 条，减小载荷；完整轨迹走 3.3）。

> 增强项（PR 可选）：`via_node` 参数匹配「途经网点」（`tracking.node` 数组内任一命中），需配套多键索引 `{"tracking.node": 1}`。

### 3.3 订单详情 `GET /orders/{orderNo}`

**响应 `200`**：完整订单文档，`tracking` 按 `time` 升序全量返回（FR-03 核心接口，走 `idx_order_no` 唯一索引）。

`404` → `code: 40401`。

### 3.4 追加物流轨迹 `POST /orders/{orderNo}/tracking`

**请求体**：

```json
{
  "time": "2026-11-18T02:30:00+08:00",
  "node": "武汉中转场",
  "action": "快件到达武汉中转场，发往北京",
  "status": "IN_TRANSIT"
}
```

**校验链（服务层顺序执行）**：

1. 订单存在，否则 `40401`；
2. `status` 为合法枚举且满足状态机（BR-01），否则 `40901`；已 `DELIVERED` 直接拒绝；
3. `time` 不早于最后一条轨迹时间（BR-02），否则 `40002`；
4. 追加成功后原子更新 `tracking`（`$push`）与 `current_status` / `current_node` / `updated_at`（`$set`），单次 `updateOne` 完成（BR-05）。

**成功响应 `200`**：更新后的完整订单文档。

### 3.5 状态统计 `GET /stats/status-count`

**响应 `200`**：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "total": 1230,
    "items": [
      { "status": "CREATED", "label": "已创建", "count": 30 },
      { "status": "PICKED_UP", "label": "已揽收", "count": 50 },
      { "status": "IN_TRANSIT", "label": "中转运输", "count": 800 },
      { "status": "OUT_FOR_DELIVERY", "label": "派送中", "count": 300 },
      { "status": "DELIVERED", "label": "已签收", "count": 50 }
    ]
  }
}
```

实现走聚合管道（02 文档 §5）；`label` 为中文名，前端直接渲染。

### 3.6 公开查单 `GET /track/{orderNo}`

面向查单用户的只读接口：返回 `order_no`、`current_status`、`current_node`、`tracking` 全量时间线；**不返回**寄件人/收件人联系方式（隐私裁剪，仅返回收件城市级信息可作为增强）。

`404` → `code: 40401`，`message: "未找到该订单，请检查单号"`。

## 4. 状态枚举值总表（前后端共享）

| value | label |
|---|---|
| `CREATED` | 已创建 |
| `PICKED_UP` | 已揽收 |
| `IN_TRANSIT` | 中转运输 |
| `OUT_FOR_DELIVERY` | 派送中 |
| `DELIVERED` | 已签收 |

## 5. 页面与接口映射（前端路由规划）

| 页面 | 路由 | 调用接口 |
|---|---|---|
| 工作台（状态统计） | `/` | 3.5 |
| 订单列表（筛选） | `/orders` | 3.2 |
| 订单详情（时间线） | `/orders/:orderNo` | 3.3、3.4 |
| 新建订单 | `/orders/new` | 3.1 |
| 公开查单 | `/track` | 3.6 |
