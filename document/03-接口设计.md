# 03 接口设计（REST API）

> 驿迹 ExpressTrace ｜ 前后端契约文档，前后端分离开发的唯一事实来源
> 约定：JSON in / JSON out；时间一律 ISO 8601（含时区）；错误统一格式

## 1. 通用约定

**Base URL**：`http://localhost:3000/api/v1`

**统一响应封装**：

```json
// 成功
{ "code": 0, "message": "ok", "data": { ... } }

// 失败
{ "code": 40401, "message": "订单不存在", "data": null }
```

**错误码表**：

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200/201 | 成功 |
| 40001 | 400 | 参数校验失败 |
| 40002 | 400 | 轨迹时间早于最后一条（违反 BR-02） |
| 40401 | 404 | 订单不存在 |
| 40402 | 404 | 集包袋不存在 |
| 40901 | 409 | 订单状态流转非法（如已签收仍追加，违反 BR-01） |
| 40902 | 409 | 袋状态流转非法（如已拆袋仍装件，违反 BR-07） |
| 40903 | 409 | 订单已在其他袋中（违反 BR-08 装件互斥） |
| 50000 | 500 | 服务器内部错误 |

**分页参数**（列表类接口）：`page`（默认 1）、`pageSize`（默认 10，最大 100）。

**分页响应结构**：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "items": [ ... ],
    "total": 123,
    "page": 1,
    "pageSize": 10
  }
}
```

## 3. 接口详情

### 3.1 创建订单 `POST /orders`

**请求体**：

```json
{
  "sender":   { "name": "张三", "phone": "13800000001", "address": "广东省深圳市南山区科技园路1号" },
  "receiver": { "name": "李四", "phone": "13900000002", "address": "北京市海淀区中关村大街2号" },
  "package":  { "weight_kg": 2.5, "quantity": 1, "category": "日用品", "remark": "易碎" }
}
```

**校验**：name/phone/address 必填；`weight_kg > 0`；`quantity` 为正整数；`category` 必填（非空字符串）。

**成功响应 `201`**：`data` 为完整订单文档，`order_no` 由后端按 BR-03 生成，`current_status = "CREATED"`，`tracking = []`，`bag_no = null`。

### 3.2 组合筛选订单 `GET /orders`

**查询参数**（均可选，AND 组合）：

| 参数 | 示例 | 说明 |
|---|---|---|
| `status` | `IN_TRANSIT` | 按当前物流状态（枚举见 02 文档 §4） |
| `node` | `武汉中转场` | 按当前网点（精确匹配 `current_node`） |
| `start` / `end` | `2026-11-01` / `2026-11-17` | 下单时间范围（闭区间） |
| `order_no` | `ET20261117` | 单号前缀模糊 |
| `bag_no` | `BG202611170001` | 按所在袋筛选（走 `idx_order_bag`） |
| `page` / `pageSize` | `1` / `10` | 分页 |

**排序**：`created_at` 倒序（走 `idx_created` 或 `idx_status_created`）。

**响应 `200`**：分页结构，`items` 为订单摘要（含 `current_status`、`current_node`、`bag_no`、`tracking` 仅留最新 1 条，减小载荷；完整轨迹走 3.3）。

> 增强项（PR 可选）：`via_node` 参数匹配「途经网点」（`tracking.node` 数组内任一命中），需配套多键索引 `{"tracking.node": 1}`。

### 3.3 订单详情 `GET /orders/{orderNo}`

**响应 `200`**：完整订单文档，`tracking` 按 `time` 升序全量返回（FR-03 核心接口，走 `idx_order_no` 唯一索引）。

`404` → `code: 40401`。

### 3.4 追加物流轨迹 `POST /orders/{orderNo}/tracking`

**请求体**：

```json
{
  "time": "2026-11-18T02:30:00+08:00",
  "node": "武汉中转场",
  "action": "快件到达武汉中转场，发往北京",
  "status": "IN_TRANSIT"
}
```

**校验链（服务层顺序执行）**：

1. 订单存在，否则 `40401`；
2. `status` 为合法枚举且满足状态机（BR-01），否则 `40901`；已 `DELIVERED` 直接拒绝；
3. `time` 不早于最后一条轨迹时间（BR-02），否则 `40002`；
4. 追加成功后原子更新 `tracking`（`$push`）与 `current_status` / `current_node` / `updated_at`（`$set`），单次 `updateOne` 完成（BR-05）。

**成功响应 `200`**：更新后的完整订单文档。

### 3.5 状态统计 `GET /stats/status-count`

**响应 `200`**：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "total": 1230,
    "items": [
      { "status": "CREATED", "label": "已创建", "count": 30 },
      { "status": "PICKED_UP", "label": "已揽收", "count": 50 },
      { "status": "IN_TRANSIT", "label": "中转运输", "count": 800 },
      { "status": "OUT_FOR_DELIVERY", "label": "派送中", "count": 300 },
      { "status": "DELIVERED", "label": "已签收", "count": 50 }
    ]
  }
}
```

实现走聚合管道（02 文档 §8），按 `current_status` 分组计数；`label` 为中文名，前端直接渲染。`items` 固定按上述 5 种状态的顺序返回，未出现的状态补 `count: 0`；无订单时 `total: 0`，仍返回全部 5 项。

### 3.6 公开查单 `GET /track/{orderNo}`

面向查单用户的只读接口：`200` 响应沿用统一封装，`data` **仅返回** `order_no`、`current_status`、`current_node`、`tracking` 四个字段。`tracking` 按 `time` 升序返回全量时间线，尚无轨迹时返回 `[]`。

隐私裁剪采用数据库字段白名单投影：**不返回** `sender`、`receiver` 整个对象（包括姓名、电话和完整地址），本版本不提供城市级地址；也不返回 `_id`、包裹信息、袋号或创建/更新时间。

`404` → `code: 40401`，`message: "未找到该订单，请检查单号"`。

### 3.7 建袋 `POST /bags`

**请求体**：

```json
{ "dest_node": "武汉中转场" }
```

**成功响应 `201`**：`data` 为袋文档，`bag_no` 由后端按 BR-06 生成（`BG`+日期+4位序列），`status = "OPEN"`，`order_nos = []`。

### 3.8 装件 `POST /bags/{bagNo}/items`

**请求体**：

```json
{ "order_no": "ET20261117000001" }
```

**校验链**：

1. 袋存在，否则 `40402`；
2. 袋状态为 `OPEN`，否则 `40902`（封袋后不可装件）；
3. 订单存在，否则 `40401`；订单未在其他袋中，否则 `40903`（BR-08 互斥）；
4. 写入：`bags.$addToSet order_nos` + `orders.$set bag_no`，两步顺序执行（先件后袋，失败可重试幂等）。

**成功响应 `200`**：更新后的袋文档。

### 3.9 袋级扫描 `POST /bags/{bagNo}/scan`（袋扫件动）

**请求体**：

```json
{
  "time": "2026-11-18T02:30:00+08:00",
  "node": "武汉中转场",
  "action": "整袋到达，待拆袋",
  "type": "ARRIVE"
}
```

**校验链**：

1. 袋存在 → `40402`；
2. `type` 驱动袋状态机合法（BR-07）→ `40902`；异常态袋（BROKEN/LOST）拒绝任何扫描；
3. `time` 不早于袋最后一条扫描时间 → `40002`；
4. **袋扫件动（FR-09，写传播）**：袋 `scans` `$push` 后，`updateMany({bag_no})` 为袋内全部件 `$push` 轨迹（`action` 带 `[袋BGxxxx]` 前缀）+ `$set` `current_node`/`updated_at`；`type = OPEN`（拆袋）时同时清空各件 `bag_no = null` 并清空袋 `order_nos` 快照归档——拆袋动作完成会籍解除；
5. `type = SEAL`/`DEPART`/`ARRIVE` 不改变件级 `current_status`（整袋流转不虚构件状态），`type = OPEN` 亦然——件状态仍由件自身扫描驱动（BR-01 语义不破坏）。

**成功响应 `200`**：`data` 含袋文档 + `propagated_count`（本次传播件数），供前端提示「已同步 N 件轨迹」。

### 3.10 标记袋异常 `POST /bags/{bagNo}/exception`

**请求体**：

```json
{ "type": "BROKEN", "action": "集包袋破损，袋内小件散落分拨中心" }
```

**校验**：`type` ∈ `BROKEN`/`LOST`；袋当前非 `OPENED`；异常态为吸收态，已异常袋拒绝重复标记（`40902`）。

**成功响应 `200`**：更新后的袋文档（`status` = 异常态，`scans` 追加 EXCEPTION 记录）。

### 3.11 影响面分析 `GET /bags/{bagNo}/impact`

**响应 `200`**（聚合管道见 02 文档 §6）：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "bag_no": "BG202611170001",
    "dest_node": "武汉中转场",
    "status": "BROKEN",
    "affected_count": 3,
    "orders": [
      { "order_no": "ET20261117000001", "current_status": "IN_TRANSIT", "current_node": "武汉中转场", "receiver_name": "李四", "receiver_phone": "13900000002" }
    ],
    "status_dist": { "IN_TRANSIT": 2, "PICKED_UP": 1 }
  }
}
```

任何状态的袋均可查影响面（正常袋查装载构成、异常袋查波及面）；`40402` 袋不存在。

### 3.12 袋列表 `GET /bags`

**查询参数**：`status`（可选，袋状态枚举）、`page` / `pageSize`（同通用约定）。

**响应 `200`**：分页结构，`items` 为袋文档数组（`created_at` 倒序）。

### 3.13 袋详情 `GET /bags/{bagNo}`

**响应 `200`**：完整袋文档，含 `scans` 时间线（按 `time` 升序）与 `order_nos` 件清单。`404` → `code: 40402`。

## 4. 状态枚举值总表（前后端共享）

**订单状态**：

| value | label |
|---|---|
| `CREATED` | 已创建 |
| `PICKED_UP` | 已揽收 |
| `IN_TRANSIT` | 中转运输 |
| `OUT_FOR_DELIVERY` | 派送中 |
| `DELIVERED` | 已签收 |

**袋状态**：

| value | label |
|---|---|
| `OPEN` | 装件中 |
| `SEALED` | 已封袋 |
| `IN_TRANSIT` | 干线在途 |
| `ARRIVED` | 已到港 |
| `OPENED` | 已拆袋 |
| `BROKEN` | 破损 |
| `LOST` | 丢失 |

**袋扫描类型**：

| value | label | 袋状态迁移 |
|---|---|---|
| `SEAL` | 封袋 | OPEN → SEALED |
| `DEPART` | 干线发运 | SEALED → IN_TRANSIT |
| `ARRIVE` | 到港 | IN_TRANSIT → ARRIVED |
| `OPEN` | 拆袋 | ARRIVED → OPENED |
| `EXCEPTION` | 异常标记 | * → BROKEN/LOST |
