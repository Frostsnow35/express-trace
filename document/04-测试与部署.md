# 04 测试与部署

> 驿迹 ExpressTrace ｜ 环境搭建、初始化、测试与备份恢复手册

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| MongoDB Community | ≥ 6.0 | 单机即可，Windows 原生或 Docker |
| Node.js | ≥ 18 LTS | 后端运行时（Express + Mongoose） |
| pnpm 或 npm | 最新稳定 | 包管理 |
| Vue | 3.x + Vite | 前端框架 |

### 1.1 Docker 一键起库（推荐）

```bash
docker run -d --name express-trace-mongo \
  -p 27017:27017 \
  -v express-trace-data:/data/db \
  mongo:7
```

### 1.2 Windows 原生安装

下载 MongoDB Community MSI，安装时勾选 *Install MongoDB as a Service*，默认端口 27017。用 `mongosh` 验证：

```bash
mongosh mongodb://127.0.0.1:27017 --eval "db.runCommand({ping:1})"
```

## 2. 数据库初始化

脚本位于 `data/`，均以 `mongosh` 执行，**可重复执行（幂等）**：

```bash
# 1) 建库、建集合、启用 JSON Schema 校验
mongosh mongodb://127.0.0.1:27017 data/init/01-create-collections.js

# 2) 建索引
mongosh mongodb://127.0.0.1:27017 data/init/02-create-indexes.js

# 3) 灌入演示数据（可选，课程演示用）
mongosh mongodb://127.0.0.1:27017 data/init/03-seed-data.js
```

初始化产物：数据库 `express_trace`、集合 `orders`（带校验 + 4 个索引 + 若干演示订单）。

## 3. 应用启动

```bash
# 后端（默认 3000 端口）
cd code/backend && npm install && npm run dev

# 前端（默认 5173 端口，代理 /api → 3000）
cd code/frontend && npm install && npm run dev
```

访问 `http://localhost:5173`；API 契约见 `document/03-接口设计.md`。

## 4. 测试计划

### 4.1 功能验收清单（对照 01 文档 §10）

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| T1 | 订单录入 | 提交合法表单 | 生成 `ET+日期+序列` 单号，状态「已创建」 |
| T2 | 订单录入-校验 | 缺收件人手机号提交 | 40001，表单红字提示 |
| T3 | 轨迹追加 | 对 T1 订单追加「已揽收」 | `tracking` 长度 1，`current_status` 同步 |
| T4 | 状态机-非法流转 | 对「已签收」订单追加轨迹 | 40901，拒绝 |
| T5 | 时序校验 | 追加时间早于最后轨迹 | 40002，拒绝 |
| T6 | 轨迹查询 | 按单号查详情 | 全部轨迹按时间升序完整返回 |
| T7 | 组合筛选 | 状态=派送中 + 时间近7天 + 网点=X | 只返回命中项，分页正确 |
| T8 | 状态统计 | 打开工作台 | 各状态数量与 `countDocuments` 手工核对一致 |
| T9 | 公开查单 | 输入单号查询 | 返回时间线，无联系方式字段 |
| T10 | 备份恢复 | dump → drop → restore | 数据完整一致 |

## 5. 备份与恢复

```bash
# 备份（备份文件放 data/backup/，带日期）
mongodump --uri="mongodb://127.0.0.1:27017" --db=express_trace --out=data/backup/$(date +%Y%m%d)

# 恢复
mongorestore --uri="mongodb://127.0.0.1:27017" --db=express_trace --drop data/backup/<日期>/express_trace
```

课程提交要求：`data/backup/` 内提交 **一份全量备份**（`mongodump` 产物）作为数据备份材料。备份前先执行 `03-seed-data.js` 保证备份非空。

## 6. 故障排查

| 现象 | 处理 |
|---|---|
| `MongoServerError: not authorized` | 检查连接串是否漏了认证库，本地单机默认无认证 |
| 前端 404（接口存在） | 检查 Vite 代理 `/api` 是否指向 3000 |
| 校验拒绝合法写入 | 检查是否漏跑 `02-create-indexes.js` 或 validator 与 02 文档字段不一致 |
| 端口占用 | `netstat -ano | findstr 27017` 找占用进程 |
