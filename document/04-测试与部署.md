# 04 测试与部署

> 驿迹 ExpressTrace ｜ 环境搭建、初始化、测试与备份恢复手册

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| MongoDB Community | ≥ 6.0 | 单机即可，Windows 原生或 Docker |
| Node.js | ≥ 18 LTS | 后端运行时（Express + Mongoose） |
| pnpm 或 npm | 最新稳定 | 包管理 |
| Vue | 3.x + Vite | 前端框架 |

### 1.1 Docker 一键起库（推荐）

```bash
docker run -d --name express-trace-mongo \
  -p 27017:27017 \
  -v express-trace-data:/data/db \
  mongo:7
```

### 1.2 Windows 原生安装

下载 MongoDB Community MSI，安装时勾选 *Install MongoDB as a Service*，默认端口 27017。用 `mongosh` 验证：

```bash
mongosh mongodb://127.0.0.1:27017 --eval "db.runCommand({ping:1})"
```

## 2. 数据库初始化

脚本位于 `data/init/`，均以 `mongosh` 执行，**可重复执行（幂等）**：

```bash
# 1) 建库、建集合（orders + bags）、启用 JSON Schema 校验
mongosh mongodb://127.0.0.1:27017 data/init/01-create-collections.js

# 2) 建索引
mongosh mongodb://127.0.0.1:27017 data/init/02-create-indexes.js

# 3) 灌入演示数据（可选，课程演示用：8 单 5 状态 + 2 袋含 1 破损异常袋）
mongosh mongodb://127.0.0.1:27017 data/init/03-seed-data.js

# 4) 备份恢复验证（T10，独立执行，非初始化必经步骤）
mongosh mongodb://127.0.0.1:27017 data/init/04-verify-backup.sh   # 见 §5，sh 脚本内含 mongodump/mongorestore
```

**Docker 容器内执行**（宿主无 mongosh 时；注意 Git Bash 路径转换坑见 §6）：

```bash
docker cp data/init express-trace-mongo:/init
MSYS_NO_PATHCONV=1 docker exec express-trace-mongo sh -c \
  "mongosh --quiet /init/01-create-collections.js && mongosh --quiet /init/02-create-indexes.js && mongosh --quiet /init/03-seed-data.js"
```

初始化产物：数据库 `express_trace`、集合 `orders` + `bags`（带校验 + 6 个索引 + 8 条演示订单 + 2 个演示袋）。幂等预期：第二轮输出「新增 0 条 / 0 个」。

#### 4.1.1 #7 接口自动验收（T8/T9）

单元测试不需要数据库，也不安装额外依赖，使用 Node.js 内置测试运行器：

```bash
npm --prefix code/backend test
```

真实 HTTP 集成测试会启动后端进程，并回归 #4 订单录入及袋级写传播。要求 Docker 已启动且本机已有 `mongo:7` 镜像，执行：

```bash
npm --prefix code/backend run test:integration
```

入口脚本自动创建随机名称的临时容器，使用 `--pull=never` 禁止自动下载，数据仅放内存、不挂载业务数据卷，端口由 Docker 动态分配且只绑定 `127.0.0.1`。**不需要也不要手工填写业务库连接串**，数据库名仍为 `express_trace`。

测试连接前会用 `docker inspect` 核对完整容器 ID、测试标签、自动移除配置、内存挂载及实际端口映射；拒绝默认业务端口 `27017`、额外连接选项或不符的容器，随后再检查目标库必须为空。直接执行底层测试文件且没有连接串时安全跳过；只有连接串、没有对应测试容器 ID 时直接拒绝，不连接数据库。

入口启动时先清扫带 `express-trace.integration=issue7` 专属 label 的遗留测试容器（外层被硬杀时的残留），只清扫本测试脚本创建的容器，不触碰业务容器。正常结束、测试失败或收到 SIGINT/SIGTERM 中断时，按**本次成功创建后返回的完整容器 ID**清理；创建失败时不会执行停止命令。测试后端使用自动选取的本机空闲端口（可用 `INTEGRATION_PORT` 覆盖），会在 `finally` 中终止并断开数据库；另外通过 IPC 监听测试父进程断开，即使外层超时强制终止测试进程，后端也会自行退出。集成测试包含真实后端就绪后强杀测试父进程、核对进程退出和端口释放的回归用例。测试不执行 `dropDatabase`，容器移除时其内存数据一并消失。

覆盖空库五状态补零、部分状态补零、全状态与 `countDocuments` 核对、完整升序时间线、仅四字段的隐私裁剪、未找到单号、查询不改变数据库，以及订单录入/集包袋基本回归。

### 4.3 写传播 vs 读推导对比实验（核心创新点实证，必做）

|---|---|---|

## 5. 备份与恢复

**统一使用 archive + gzip 格式**（mongodump 100.20.x 的目录格式恢复存在「don't know what to do with file」解析缺陷，勿用 `--out=` 目录格式）：

```bash
# 备份（产物放 data/backup/，带日期）
mongodump --uri="mongodb://127.0.0.1:27017" --db=express_trace \
  --archive=data/backup/express_trace_$(date +%Y%m%d).archive.gz --gzip

# 恢复
mongorestore --uri="mongodb://127.0.0.1:27017" --db=express_trace --drop \
  --archive=data/backup/express_trace_<日期>.archive.gz --gzip

# 恢复后必须重建索引（archive 不携带索引定义）
mongosh mongodb://127.0.0.1:27017 data/init/02-create-indexes.js
```

一键验证：`data/init/04-verify-backup.sh`（seed → dump → drop → restore → count，对照 T10）。

课程提交要求：`data/backup/` 内提交 **一份全量备份**（archive.gz 产物）作为数据备份材料。备份前先执行 `03-seed-data.js` 保证备份非空（含订单与袋）。

## 6. 故障排查

| 现象 | 处理 |
|---|---|
| `MongoServerError: not authorized` | 检查连接串是否漏了认证库，本地单机默认无认证 |
| 前端 404（接口存在） | 检查 Vite 代理 `/api` 是否指向 3000 |
| 校验拒绝合法写入 | 检查是否漏跑 `02-create-indexes.js` 或 validator 与 02 文档字段不一致 |
| 袋扫件动未生效 | 检查件 `bag_no` 是否写入（装件接口 3.8 步骤 4）、`idx_order_bag` 是否建立 |
| 端口占用 | `netstat -ano \| findstr 27017` 找占用进程 |
| Git Bash 把容器内路径 `/init/...`、`/dump/...` 翻译成宿主路径导致 ENOENT | 命令前加 `MSYS_NO_PATHCONV=1`，或用 `docker exec ... sh -c "..."` 把路径留在容器内解析 |
| `mongorestore` 恢复目录格式 dump 报「don't know what to do with file ... skipping」且 0 条恢复 | 100.20.x 工具缺陷，改用 `--archive=xxx --gzip` 格式（§5 已固化） |
| Docker 拉镜像报 `connectex: No connection could be made ... 127.0.0.1:7890` | 系统代理指向了未运行的代理端口；将系统代理改为实际可用端口（与 `HTTP_PROXY` 环境变量一致）后**重启 Docker Desktop**（代理配置启动时缓存） |
| `git push` 报 `Out of memory, malloc failed` | 打包内存暴涨，用 `git -c pack.windowMemory=16m -c pack.threads=1 push` 重推 |
