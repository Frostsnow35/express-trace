# 01 需求分析

> 驿迹 ExpressTrace — 基于 MongoDB 的快递物流轨迹追踪系统
> 文档版本：v1.0 ｜ 主理人维护，改动须经 PR 评审

## 1. 选题背景

快递订单从创建到签收会产生一连串时序流转记录（揽收、中转、派送……），核心数据特征是：

- **一单多轨迹**：一条订单对应多条按时间生成的物流轨迹记录；
- **读多写少**：轨迹以追加为主，历史轨迹不修改；查询（按单号查全程）远多于写入；
- **文档形态天然契合**：订单基础信息 + 轨迹数组适合用 MongoDB 文档模型承载。

本系统面向快递物流业务场景，实现快递订单与物流流转记录的管理，业务覆盖订单从**创建 → 揽收 → 中转 → 派送 → 签收**的完整流程。

## 3. 角色划分（标准版无登录，按使用场景划分）

| 角色 | 使用入口 | 职责 |
|---|---|---|
| 业务操作员 | 管理端页面 | 录入订单、追加物流轨迹、组合筛选、查看状态统计 |
| 查单用户 | 公开查单页 | 凭订单编号查询该订单全部物流轨迹 |

## 4. 功能需求

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-01 | 订单录入 | 录入寄件人、收件人、包裹信息（重量、件数、品类、备注），系统生成唯一订单编号，初始状态为「已创建」 | P0 |
| FR-02 | 轨迹追加 | 对指定订单追加一条物流轨迹：流转时间、所在网点、物流操作说明、物流状态；追加后订单当前状态与当前网点同步为该轨迹的值 | P0 |
| FR-03 | 轨迹查询 | 根据订单编号查询该订单全部物流历史，按流转时间升序展示完整时间线 | P0 |
| FR-04 | 订单筛选 | 按物流状态、时间范围（下单时间）、网点（轨迹途经网点）等条件组合筛选订单，分页返回 | P0 |
| FR-05 | 状态统计 | 统计不同物流状态的订单数量（含总量），用于运营看板 | P0 |
| FR-06 | 公开查单 | 面向查单用户的只读页面：输入订单编号，展示订单当前状态与全部轨迹 | P1 |
| FR-07 | 订单状态机校验 | 轨迹追加时校验状态流转合法性与时间单调性，非法流转拒绝并提示 | P0 |

## 5. 业务规则

**BR-01 状态机**（单向推进，「中转」可出现多次，「已签收」为终态）：

```
已创建 → 已揽收 → 中转运输 → 派送中 → 已签收
  └──────────────────────────────────┘（签收后禁止任何追加/修改）
```

**BR-02 轨迹时序**：新轨迹的流转时间不得早于该订单最后一条轨迹的流转时间。

**BR-03 订单编号**：全局唯一、生成后不可修改，格式 `ET` + `yyyyMMdd` + 6 位序列（如 `ET20261117000001`）。

**BR-04 轨迹只增不改**：轨迹为追加型记录，不提供修改/删除历史轨迹的接口（数据可信度要求）。

**BR-05 冗余字段**：订单文档顶层的 `current_status` / `current_node` 始终等于最新一条轨迹的值，随追加同步更新（反范式，服务筛选与统计）。

## 6. 数据需求

| 数据实体 | 关键属性 | 说明 |
|---|---|---|
| 快递订单 | 订单编号、寄件人、收件人、包裹信息、当前物流状态、当前网点、下单时间 | 主实体 |
| 物流轨迹 | 流转时间、所在网点、物流操作说明、物流状态 | 时序子记录，一单多条 |

约束：一条订单对应 1..N 条物流轨迹；订单创建时可暂无轨迹（仅「已创建」状态）。

## 7. 非功能需求

| 维度 | 目标 |
|---|---|
| 数据规模 | 支撑 10 万级订单、单订单数十条轨迹的课程演示规模；文档设计预留扩展说明 |
| 查询性能 | 按单号查轨迹 < 100ms（走唯一索引）；组合筛选走复合索引，`explain` 验证不走全表扫描 |
| 易用性 | 管理端表单 + 时间线可视化；查单页一输入框即可用 |
| 可维护性 | 前后端分离、接口契约化、初始化脚本可重复执行 |
| 数据可信 | 轨迹只增不改，状态流转有校验，数据可备份恢复 |

## 8. 范围边界（Out of Scope）

标准版明确**不做**：账号登录与权限、支付、短信/推送通知、快递员与网点档案管理（网点作为轨迹中的文本字段）、地图轨迹可视化、订单取消/退款、轨迹修改与删除。

## 9. 用例清单

| 编号 | 用例 | 角色 | 对应功能 |
|---|---|---|---|
| UC-01 | 录入一笔新订单 | 业务操作员 | FR-01 |
| UC-02 | 对订单追加一条揽收/中转/派送/签收轨迹 | 业务操作员 | FR-02 / FR-07 |
| UC-03 | 输入订单编号查看完整物流时间线 | 业务操作员 / 查单用户 | FR-03 / FR-06 |
| UC-04 | 按「派送中 + 近 7 天 + 某网点」筛选订单 | 业务操作员 | FR-04 |
| UC-05 | 查看各状态订单数量统计 | 业务操作员 | FR-05 |

## 10. 验收标准（摘要）

1. 可完成 UC-01 ~ UC-05 全部用例；
2. 非法状态流转（如签收后再追加）被拒绝并给出明确提示；
3. `explain()` 证明单号查询与组合筛选命中索引；
4. 初始化脚本可对空库一键建集合/索引/造数；
5. `mongodump` / `mongorestore` 备份恢复流程可复现。
