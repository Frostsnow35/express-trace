# 07 开发规格

> 驿迹 ExpressTrace ｜ 代码级验收口径 ｜ 与 AGENTS.md（协作）互补，冲突时 AGENTS.md 优先
> 适用：所有 backend/frontend/data 交付物

## 1. 技术栈与工程结构（冻结，变更须提 issue）

| 端 | 栈 | 结构 |
|---|---|---|
| 后端 | Node.js 18+ / Express / Mongoose / ES modules | `src/routes → controllers → services → models → middlewares`，业务校验在 services |
| 前端 | Vue 3 / Vite / Axios | `views / components / api / router`，状态枚举常量单一来源 |
| 数据 | MongoDB 6+，库 `express_trace`，集合 `orders` `bags` | 字段名/枚举值与 document/02 逐字一致，禁止私造别名 |

## 2. 接口契约

- 唯一事实来源：`document/03-接口设计.md`；实现与文档冲突时**改代码服从文档**或走 PR 同步改文档，禁止静默偏离；
- 统一响应 `{code, message, data}`；错误码只用 03 §1 表内值，新增错误码先改文档；
- 时间字段一律 ISO 8601 入参、Date 存储。

## 3. 数据规则

- 订单号 `ET`+`yyyyMMdd`+6位序列（并发安全：`findOneAndUpdate`+`$inc`，禁止查最大值+1）；袋号 `BG`+`yyyyMMdd`+4位序列；
- 订单状态机 / 袋状态机 / 装件互斥（BR-01/07/08）校验全部在 service 层，controller 只做参数解析；
- 轨迹只增不改（BR-04）；袋扫件动写入的轨迹 `action` 必带 `[袋BGxxxx]` 前缀（BR-09）；
- 冗余字段（`current_status`/`current_node`/`bag_no`）与明细一致是硬约束，每次写入后自检一次。

## 4. 代码规范

- ES modules（`type: "module"`）；camelCase 命名；禁 `var`；关键分支（状态机/时序/互斥）必有注释指明 BR 编号；
- 无硬编码密钥（`.env.example` 交付）；输入参数在 controller 层白名单校验；
- 每个 service 导出纯函数优先，便于单测；错误抛出用统一 `ApiError(code, message)`。

## 5. 数据脚本规范（data/init）

- 幂等：重复执行不报错、不重复造数（upsert / createIndex 幂等 / validator 覆盖写）；
- 三个脚本顺序执行可从空库到可用库；脚本头部注释标注用法；
- 种子数据覆盖：订单 5 种状态各 ≥1 条 + 演示袋 ≥1 个（含装件与扫描记录）。
